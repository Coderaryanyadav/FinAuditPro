## Executive Summary

This document catalogues pure domain engines, persistence models, analytics routines, and UI controls within FinAuditPro that exist in the codebase but are **orphaned** (i.e. disconnected from the primary statutory audit lifecycle, lacking UI execution paths, or producing outputs that cannot transition into downstream audit working papers).

---

## 1. Analytics Engines that Produce Results but Cannot Create Audit Work

| Orphaned Engine | Source File | Capability Implemented | Why It Is Orphaned / Disconnected |
|---|---|---|---|
| **Cut-Off Testing Engine** | `src/finauditpro/domain/cutoff_testing_engine.py` | Validates $\pm 10$ day year-end transactions for unbilled dispatches, post-closing sales returns, and late purchases. | Defined and unit-tested in isolation, but no application service or UI button invokes it directly from `FinancialDataView` or `WorkingPaperView`. |
| **Three-Way Match Engine** | `src/finauditpro/domain/three_way_match_engine.py` | Compares PO, GRN, and Vendor Invoices for price/quantity variances and unauthorized purchases. | Domain logic exists, but there is no ingestion UI to upload separate PO and GRN datasets in `FinancialDataView`. |
| **Payroll Forensic Engine** | `src/finauditpro/domain/payroll_forensic_engine.py` | Detects duplicate bank accounts, round-sum salary anomalies, and ghost employee payroll payments. | Engine exists in domain, but no dedicated view or tab triggers payroll forensic scans. |
| **ROC Secretarial Engine** | `src/finauditpro/domain/roc_secretarial_engine.py` | Validates MCA filings, DIN status, shareholding changes, and charge registration under Companies Act. | Pure domain engine with zero application service or UI wiring. |
| **Minutes Contradiction Engine**| `src/finauditpro/domain/minutes_contradiction_engine.py`| Compares Board of Directors meeting minutes text against financial statement transactions. | No UI or service pipeline invokes this comparison. |
| **Receivables Recovery Engine** | `src/finauditpro/domain/receivables_recovery_engine.py`| Evaluates post-balance-sheet collections against debtor balances for ECL / provisioning under SA 540. | Logic is implemented, but not connected to Working Paper B-40 (Trade Receivables). |
| **Continuous Audit Service** | `src/finauditpro/application/services/continuous_audit_service.py` | Scans for periodic drift and generates continuous reconciliation alerts. | No background worker or cron scheduler executes this service in production. |

## 2. Evidence & Document Links Without Downstream Action

| Orphaned Evidence Capability | Location | Issue Description |
|---|---|---|
| **Dual Evidence Persistence Tables** | `evidence_links` table vs `audit_evidence` table | Two parallel models (`EvidenceLinkModel` in `models.py` and `AuditEvidenceModel` in `pbc_and_query_models.py`) store evidence attachments independently without cross-synchronization. |
| **Evidence Pinned to Inactive Finding** | `src/finauditpro/ui/dialogs/document_viewer_dialog.py` | Bounding box snippets can be pinned to findings, but if the finding is deleted or merged, the evidence link remains dangling without cascade or warning. |
| **FTS Document Snippets to Procedure Link** | `src/finauditpro/ui/views/document_view.py` | Search results from SQLite FTS5 can be previewed, but cannot be directly attached as supporting documentation to an audit procedure in `AuditMatrixView`. |

## 3. Findings & Working Papers Without Direct Procedure Provenance

| Disconnected Concept | Location | Issue Description |
|---|---|---|
| **Manual Findings without Procedure / Risk ID** | `src/finauditpro/ui/dialogs/finding_dialog.py` | When a user clicks "+ New Finding", the `procedure_id` and `risk_id` fields are optional and default to `None`, creating orphan findings untraceable to any SA 315 risk. |
| **Working Papers without Linked Procedures** | `src/finauditpro/ui/views/working_paper_view.py` | Default Schedule III working papers (B-10 to C-50) generated by `WorkingPaperScaffolder` do not automatically attach the corresponding statutory procedures from `methodology_catalog.py`. |
| **Standalone Risks Without Procedures** | `src/finauditpro/ui/dialogs/risk_dialog.py` | A user can create a High-RoMM risk under SA 315 without being prompted to formulate an audit response / procedure under SA 330. |

## 4. Dashboard Metrics Without Real Underlying Data Sources

| Dashboard Metric | Location | Hardcoded / Approximate Implementation | Required Canonical Source |
|---|---|---|---|
| **"Ready for Partner Sign-off" Status** | `EngagementService.get_engagement_dashboard()` | Calculated purely as `total_wps > 0 and open_wps == 0`, ignoring unaddressed review notes or missing mandatory checklists. | Must be derived from `FinalizationGateEngine.evaluate_gate_status()`. |
| **"Financial Data Status" Banner** | `src/finauditpro/ui/views/dashboard_view.py` | Shows "Imported" if any dataset exists, but does not verify whether current year TB is balanced ($Dr = Cr$) or mapped to Schedule III. | Must verify `FinancialDatasetModel.is_balanced` and `AccountMappingRepository.get_unmapped_count()`. |
| **"Risk Profile Summary" Donut Chart** | `src/finauditpro/ui/views/dashboard_view.py` | If 0 risks are recorded in `audit_risks`, displays an empty placeholder rather than warning that Planning (SA 315) is incomplete. | Must flag SA 315 non-compliance when risk count is zero. |

## 5. Architectural Remediation Plan

1. **Step 1:** Bridge the `CutOffTestingEngine`, `BankReconciliationEngine`, and `FixedAssetEngine` directly into the substantive testing grid of the corresponding Working Papers (C-10, B-90, B-30).
2. **Step 2:** Merge the dual evidence tables (`evidence_links` and `audit_evidence`) into a single canonical evidence model.
3. **Step 3:** Enforce mandatory selection of `risk_id` and `procedure_id` when raising findings and exceptions.
4. **Step 4:** Ensure `WorkingPaperScaffolder` populates standard ICAI audit procedures into each scaffolded workpaper.
